# 发布时间线参考

时间均为经验值，不是硬规则。用户的历史 `launch/log.md` 数据优先于本表。

## arXiv 节奏（决定首发日）

- arXiv 新论文在**美东时间周日至周四 20:00** 公布（对应北京时间次日 08:00–09:00）。周五、周六不公布。
- 提交截止约为美东 14:00；当天截止前提交，当晚公布。
- 首发帖应在 arXiv 页面**已经能打开之后**发，链接才不会是 404。

## 首发日推荐顺序（场景 A）

| 时间（美东 / 北京，夏令时） | 动作 | 谁做 |
|---|---|---|
| 前 1–2 天 | brief、README、主页、thread、小红书草稿全部就绪；主页先部署但不宣传 | agent |
| arXiv 公布后 | 检查 arXiv 链接、主页、仓库都可访问；README 里的链接替换成正式地址 | agent |
| 美东 9:00 / 北京 21:00（周二至周四最佳） | 发 X thread，置顶 | 用户 |
| 同时 | 在 huggingface.co/papers 提交该 arXiv 论文（"Submit paper"），作者可认领 | 用户 |
| 发完 thread 后 | 请合作者/导师转发或引用转发（给他们发 thread 链接即可） | 用户 |
| 北京 19:00–22:00 | 发小红书笔记（与 X 同一天或次日均可） | 用户 |
| 发布后 1–2 天 | 回复评论区问题；把好问题沉淀进主页 FAQ（可选） | 用户 + agent |

冬令时美东与北京相差 13 小时，美东 9:00 = 北京 22:00。

## 场景 B：中稿

- X：引用转发（quote）自己的首发 thread + 一句话 + venue 名。不新开长 thread。
- 小红书：中稿是小红书最受欢迎的科研题材之一，重点写**过程与感受**（需要用户提供素材），技术内容压缩到 2–3 张卡。
- README / 主页：更新 venue 徽章与 BibTeX。

## 场景 C：参会

- 会前 1–3 天：X 帖"来 #XX 号展板找我"，附海报缩略图、展位号、时段、主页链接。
- 会议当天：可在 X 上转发自己的帖子提醒。
- 会后 1 周内：小红书参会笔记（现场照片、海报前合影、见到的人和收获），用户提供照片，你写文案和排图。

## 场景 D：新版本

- X：单条帖子 + 演示 GIF/视频，或 3–4 条的短 thread。
- 小红书：只有当有"能看得懂的效果演示"时才发，否则跳过。
